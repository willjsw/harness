## 출력

```
## work 결과 (#<이슈번호>)

- 브랜치: <태그>/<번호>-<요약>
- task 이슈: T1 #6 · T2 #7 · … (생성 <N>건 / 기존 <N>건)   (또는 "해당 없음 — 분해 없는 단독 task")
- MR: <URL>  (리뷰 루프 N회)
- 최종 판정: PASS(blocker·major 0건) | 상한 도달(회차 | 반복 지적) | 중단(<사유>)
- 검증: script/run-lint-test.sh <통과|실패>

### 루프 기록
| 회차 | 리뷰 발견 (blocker/major/minor) | 조치 |
|---|---|---|
| 1 | 2 / 1 / 3 | … |
| 2 | 0 / 0 / 1 | … |

### 남은 것
- 미해결 발견과 그 사유 — 고치지 않고 넘긴 것은 이월 이슈 번호 또는 반증 근거를 함께
- 반복된 지적이 있으면 그 내용과 명세 되돌림 제안
```

## 하지 않는 것

- MR 머지, 이슈 종료 — 사람이 한다. **이슈를 직접 닫지 않는다. task 이슈도 마찬가지다.**
  닫는 것은 머지다 — MR 본문의 `Closes` 참조를 forge 가 그때 처리한다.
- 리뷰 스레드 resolve — 조치했다는 답글만 남기고 닫는 것은 리뷰어·사람이 한다.
- `docs/plan/<번호>/task.md` 수정 — 승인된 분해다. 어긋나면 고치지 말고 보고한다.
- 이슈 본문 수정 — 단독 task 경로에서 이것이 완료 조건의 정본이다. 어긋나면 보고한다.
- 명세에 없는 기능 추가 — 필요해 보이면 보고한다.
- 판정을 통과시키기 위한 테스트 약화·assertion 삭제.
