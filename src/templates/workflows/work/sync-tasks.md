
**판정이 `plan` 일 때만 돈다.** `standalone` 이면 이 단계를 건너뛰고 {{step:implement}}단계로 간다 —
그 이슈 자신이 구현 단위이므로 만들 하위 이슈가 없다. 스크립트를 부르지 않는다.

```bash
script/sync-task-issues.sh <이슈번호>
```

`docs/plan/<번호>/task.md` 의 각 절을 이슈 제목으로 대조해 **없는 것만 만든다.** 이미 열려 있거나
닫힌 이슈는 건너뛴다. 출력은 `T1 #6 skip(opened)` 형식의 매핑이고, 구현자가 커밋 메시지의
이슈 번호를 여기서 얻는다.

- 종료 코드가 0이 아니면 **구현을 시작하지 않는다.** 이슈 번호 없이는 커밋이 훅에 막힌다.
- **경합을 만나면 아무것도 만들지 않고 멈춘다.** 같은 이슈에 다른 실행이 돌고 있거나, 계획을
  세운 뒤에 task 이슈가 생겼거나, 같은 제목이 이미 둘 이상이면 그렇다. 출력이 충돌 지점을
  지목한다 — **손으로 이슈를 만들어 우회하지 않는다.** 사유를 그대로 보고하고 사람에게 넘긴다.
- 스크립트는 로컬 작업 트리가 아니라 **방금 fetch 한 원격 통합 브랜치의 `task.md` 를 읽는다.** 승인된
  분해로만 이슈가 생긴다는 게이트를 스크립트 자신이 지킨다
  머지 전이면 여기서 멈추므로 착수 판정의 열린 MR 검사와 층이 겹친다.
