## 전 task 공통 사항

- 판정은 셸과 표준 도구(`sed` · `awk` · `tr` · `grep` · `git`)만으로 한다. python3 를 부르지 않는다(명세 1). `awk` · `sed` 는
  macOS 기본 도구와 CI(ubuntu) 기본 도구에서 같게 도는 형태만 쓴다 — gawk 전용 기능이나 GNU 전용 옵션을 쓰지 않는다
- 가드 6종의 규칙 · 순서 · 차단 문구 · 안내 · 사용 기록 라벨은 바꾸지 않는다(명세 1)
- 가드 함수는 지금처럼 `$CMD` 를 판정하고, `_guards.sh` 는 읽기만 해서는 판정을 돌리지 않는다. 비교 값 검사가 `_guards.sh` 를
  읽고 `CMD` 를 넣어 가드를 직접 부른다
- 가드 함수 정의 줄(`guard_<이름>() {`)의 모양을 바꾸지 않는다. 망가뜨린 가드 사본 검사가 그 줄을 `sed` 로 바꿔 끼운다
- 기존 케이스와 기대값, 망가뜨린 가드 사본 검사 둘, 비교 값 검사는 그대로 둔다(명세 6-5). 명세 10절의 미탐은 회귀 케이스로
  고정하지 않는다. `src/test/render-test.sh` 는 고치지 않는다
- 케이스 값은 기존 표처럼 설정에서 받는다(`protected_a` · `protected_b` · `work_branch` · `doc` · `doc_name` · `forge_cli`).
  보호 문서 경로를 명령 문자열에 적어 Bash 도구로 돌리지 않는다 — 작업 세션의 보호 문서 가드가 명령 문자열 전체를 보고 막는다
- `git commit` 을 실행하고 0 을 기대하는 케이스는 "브랜치에 따라 갈리는 commit 판정" 절의 작업 브랜치 임시 리포에서 돈다.
  `case_is` 는 테스트를 돌리는 작업 트리의 브랜치로 commit 을 판정하므로, 보호 브랜치에서 돌면 보호 브랜치 commit 가드가 막는다
- 정본(`src/templates/managed/script/`)을 고친 뒤 `src/bin/harness render` 로 이 리포의 `script/` 사본과 `.harness/managed` 를
  갱신해 함께 커밋한다. `script/test-bash-guard.sh` 는 설치된 사본(`script/hooks/`)을 부르므로 render 뒤에 돌린다
- render 가 `script/hooks/` 를 바꾸면 작업 세션의 다음 Bash 호출부터 새 판정이 돈다(명세 7). T2 · T3 은 render 전에 정본
  `bash-guard.sh` · `_guards.sh` 를 `sh -n` 으로 구문 확인한다
- 주석과 테스트 이름에 이슈 번호 · 문서 번호 · 테스트 항목 ID 를 넣지 않는다. 동작이 바뀌어 틀리게 된 주석은 그 동작을 바꾸는
  task 에서 고친다
- 커밋 전 `script/run-lint-test.sh --commit` 과 `script/test-bash-guard.sh` 가 통과한다. 이 리포는 `[verify]` 의
  `script_tests = false` 라 커밋 단계 검증이 `test-bash-guard.sh` 를 돌리지 않는다. push 전 검증은 `render-test.sh` 의 설치본
  블록에서 이 테스트를 돌린다

## 이번 이슈에서 다루지 않는 것

- 명세 10절의 한계 — 명령 치환 안 히어독(`git commit -m "$(cat <<'EOF' …)"`) 뒤의 명령, 주석 안 따옴표가 뒤 줄과 짝지어지는
  경우, 매개변수 확장 `${…}` 안의 `<<`, 셸이 그렇게 실행하지 않아도 기존 판정이 내는 차단, `\u000a` 같은 다른 줄바꿈 표기
- 큰따옴표 안 명령 치환 속 히어독의 분해
- 명령 가드의 Python 이식 — #210 이 맡는다
- Codex 훅 연결 — `src/templates/vendors.toml` 의 `hooks = false` 그대로
- 보호 문서 가드의 문자열 판정에서 오는 한 줄 명령의 오탐(커밋 메시지에 적은 보호 문서 경로와 쓰기 명령 이름)
- Claude Code 권한 deny 규칙이 여러 줄 명령을 판정하는 방식
