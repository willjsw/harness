## 전 task 공통 사항

- 바뀌는 것은 문서뿐이다. 하네스 코드(CLI · 레지스트리 클라이언트), 설정 키, 생성 파일 정의, 회귀 테스트를 고치지 않는다.
  Harbor 를 이름으로 가르는 코드를 두지 않는다(명세 1절)
- 공개 기록에서 빼는 것(명세 2-5)을 문서 · 커밋 메시지 · 리뷰 요청 본문 · 이슈 댓글 어디에도 적지 않는다
  - Harbor 의 호스트 이름 · 주소, 프로젝트 · 저장소 이름, 전체 참조
  - robot 계정 · 개발자 계정의 이름, 자격증명 · 토큰
  - 실측한 인스턴스의 정책 설정 — 불변 규칙의 패턴, 서명 도구와 그 설정, 보존 정책
  - 내부 URL(CI 실행 기록 링크 포함), 명령 출력 원문
  - 실측한 인스턴스가 조직이 운영하는 것이라는 사실
- 실측 입력 댓글에 없는 Harbor 사실을 지어내지 않는다. 문서에 필요해지면 멈추고 필요한 관측 항목을 보고한다(명세 5절)
- 실측 입력은 이슈 #219 의 가장 최근 `## 실측 입력 — Harbor` 댓글이다. `.ai/forge.md` 의 이슈 조회 명령으로 댓글까지 읽는다
- 운영 안내의 정본은 `src/templates/managed/docs/workflow/` 다. 정본을 고친 뒤 `src/bin/harness render` 로 이 리포의
  `docs/workflow/` 사본과 `.harness/managed` 를 갱신해 함께 커밋한다. 사본을 직접 고치지 않는다
- 운영 안내는 대상 리포의 `docs/workflow/` 에도 깔리는 관리 문서다
  - 대상 리포에 없는 이 리포의 파일(`README.md` · `docs/spec/` 등)을 상대 경로로 가리키지 않는다. 지원 목록은 하네스 리포
    README "지원 범위" 절의 절대 주소 `https://github.com/willjsw/harness/blob/main/README.md#지원-범위` 로 잇는다 — 대상
    리포가 설치하는 것은 `main` 의 릴리스다
  - 백틱으로 적는 리포 경로(`.ai/` · `.claude/` · `.codex/` · `script/` · `docs/` 로 시작하는 것)는 대상 리포에도 깔리는
    파일만 쓴다. `harness doctor` 의 references 절이 문서에 적힌 그 경로의 실재를 본다
- 문서 본문은 한국어다. 명령 · check 항목 이름 · 값은 원문 그대로 둔다
- 커밋 전 `script/run-lint-test.sh --commit` 이 통과한다
