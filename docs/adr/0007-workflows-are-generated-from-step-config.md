# 7. Workflows are generated from step config

Date: 2026-09-24

## Status

Accepted

## Context

절차 문서(`.ai/workflows/`)가 관리 파일이라 프로젝트가 단계를 바꿀 수 없었다. 끼워 넣어도 다음 갱신이
덮는다. 절차 안의 단계는 서로를 "4-1" 같은 번호로 가리켜, 순서를 바꾸면 참조가 끊겼다.

검토한 대안.

- 절차를 소유 파일로. 하네스가 절차를 고칠 수 없고, 프로젝트가 하네스 개정을 받지 못한다
- 프로젝트가 관리 파일을 고치고 갱신 때 병합. 문서 병합은 예측되지 않는다(0002)

## Decision

우리는 절차의 단계 순서·종류·제목을 `harness.toml` 의 `workflows.<절차>.steps` 에 두고 render 가
절차 문서를 만들게 한다. 단계 본문은 조각(`templates/workflows/<절차>/<id>.md`)이고, 조각은 다른 단계를
번호가 아니라 id 로 가리킨다. 가리켜진 단계를 빼면 render 가 거부한다. 프로젝트는 절차를 더하고 이름을
바꾸고 지울 수 있으며, 하네스 기본 절차는 지우면 기본값으로 돌아온다.

## Consequences

- 기본 설정으로 만든 절차는 이관 전 파일과 바이트 단위로 같아야 했다 — 그것이 이관의 검증이었다
- 단계 종류는 넷(agent·script·prompt·gate)이고 UI 는 그 종류만 그린다
- 절차별 프로젝트 지시는 소유 파일에 두고 render 가 끝에 붙인다. 절차 자체는 결정 기록 대상이
  아니다(`.ai/adr.md`) — 돌려보며 고치는 것이다
