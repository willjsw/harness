# 3. Implementer and reviewer run on different agents

Date: 2026-09-23

## Status

Accepted

## Context

리뷰 루프는 구현자가 낸 변경을 리뷰어가 보고, 지적을 구현자가 고치는 반복이다. 같은 모델이 자기 코드를
리뷰하면 같은 맹점을 두 번 지나간다 — 구현할 때 놓친 것을 리뷰에서도 놓친다.

검토한 대안.

- 프롬프트로만 분리("리뷰어 관점으로"). 모델의 사전 지식과 편향은 프롬프트로 바뀌지 않는다
- 사람이 매번 확인. 루프의 목적이 사람의 확인 횟수를 줄이는 것이다

## Decision

우리는 구현자와 리뷰어의 러너가 같으면 `render` 를 거부하기로 한다(`invariants.distinct_reviewer`).
어느 역할끼리 달라야 하는지는 역할 선언의 `distinct_from` 이 정하고, 설정은 그것을 켜고 끌 뿐이다.

## Consequences

- 오케스트레이터를 바꾸다 리뷰어와 같은 러너가 되면 설정이 성립하지 않는다. `set` 이 여러 값을 함께
  받아 한 번에 맞바꾸는 이유다
- 두 에이전트 CLI 가 필요하다. 하나만 있는 기기는 불변식을 끄거나 리뷰어를 사람이 맡는다
- 리뷰어가 CLI 러너인 경우가 기본이라, 역할을 CLI 로 띄우는 공용 실행기(`run-agent.py`)와 벤더 선언이
  같이 필요해졌다(0008)
