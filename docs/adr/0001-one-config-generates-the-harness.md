# 1. One config generates the harness

Date: 2026-09-23

## Status

Accepted

## Context

하네스는 규칙 문서·git 훅·권한 파일·에이전트 정의·절차 문서 한 벌이고, 같은 값(보호 브랜치·커밋 태그·
리뷰 상한·역할 배정·forge 종류)이 그 파일 여러 곳에 나타난다. 값을 바꿀 때 고칠 곳이 여럿이면 한 곳이
낡는다 — 커밋 제목 검사식과 그 안내문이 어긋나는 식이다.

검토한 대안.

- 설치할 때 한 번 치환하는 스캐폴딩. 설치 순간에만 단일 지점이고, 운영 중에 값을 바꾸면 다시 여러 곳을
  손으로 고쳐야 한다
- "고치지 마세요" 라는 문서 안내. 아무도 검사하지 않으므로 어긋난 채 지나간다
- 설정 형식으로 YAML. `yq` 나 `PyYAML` 이 필요하다. TOML 은 `tomllib` 가 python 표준 라이브러리라
  의존성이 0 이고, 주석을 쓸 수 있어 설정 파일이 곧 스키마 문서가 된다

## Decision

우리는 `harness.toml` 하나를 정본으로 두고 모든 하네스 파일을 거기서 생성하기로 한다. 생성 파일은
손으로 고치지 않고 `render` 로 다시 만들며, `check` 가 설정과의 일치를 검사하고 pre-commit 이 어긋난
커밋을 막는다. 문서로 지키지 않고 검사로 지킨다.

## Consequences

- 값을 바꿀 때 고치는 곳이 언제나 한 곳이다. 검사식과 안내문처럼 짝을 이루는 것이 어긋날 수 없다
- 새 생성 파일은 `plan()` 에 등록해야 한다. 등록하지 않은 생성물은 `check` 가 지키지 못하고 `render` 가
  지우지 못한다
- 소유 파일을 고치고 `render` 를 잊으면 커밋이 막힌다. 불편이지만 어긋난 채 지나가는 것보다 낫다
- 설정이 더는 만들지 않는 파일은 다음 `render` 가 지운다 — 옛 어댑터가 남아 어느 쪽이 현재인지 알 수
  없게 되는 일이 없다
