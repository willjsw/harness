# 16. Machine-local state is keyed by clone

Date: 2026-09-29

## Status

Proposed

Supersedes [10. Run metrics are local span files](0010-run-metrics-are-local-span-files.md)

## Context

기기 단위 상태(설치 등록부 · 실행 지표 · 사용 기록 · 가져오기 커서 · 이슈 worktree)는 홈 아래
`~/.harness/<프로젝트 이름>/` 으로 나뉜다. 0010 이 지표 위치를, 0009 가 등록부 위치를 그렇게 적었다.
프로젝트 이름은 커밋되는 설정 값(`project.name`)이라 같은 리포의 클론은 모두 같은 이름을 갖는다. 그래서 한
기기에 같은 리포를 두 번 클론하면 등록과 기록이 한 자리에서 섞이고, 등록부는 이름 하나에 경로 하나만 가질 수
있어 두 번째 설치를 거부해야 했다.

제약.

- 생성 파일(`script/harness.plan.json` 의 지표 경로, `script/harness.env` 의 `USAGE_LOG_PATH`)은 커밋되고 모든
  클론에서 같아야 한다 — `harness check` 가 어긋남을 막는다. 기기 로컬 키는 렌더할 때가 아니라 실행할 때 계산해야 한다
- 한 클론의 이슈 worktree(`harness run --worktree`)는 그 클론의 등록과 기록을 이어 써야 한다 — 세션 가져오기가
  worktree 실행을 본 클론의 run 에 붙인다
- 모노레포는 서브프로젝트마다 하네스를 따로 깐다. 같은 리포 안의 두 하네스 루트는 다른 상태를 가져야 한다
- 키는 기록 경로에 들어가 UI 라우트에도 보이므로 원래 경로를 드러내지 않아야 한다
- 옛 버전이 `~/.harness/<이름>/` 에 남긴 기록이 이미 기기마다 있다

검토한 대안.

- 하네스 루트 절대 경로의 해시. worktree 는 루트 경로가 달라 키가 달라지므로, worktree 에서 본 클론 경로로
  되돌리는 규칙이 따로 필요하다. 그 규칙이 git 공통 디렉터리를 읽는 것이라 결국 같은 입력을 쓴다
- 설치할 때 만든 난수 ID 를 리포 안 무시 파일에 둔다. 저장할 상태와 그것을 잃었을 때의 복구 규칙이 새로 생기고,
  클론 디렉터리를 복사하면 ID 도 복제되어 두 클론이 한 키를 쓴다
- 등록부를 `<이름>/<키>/` 로 두 단계로 둔다. 이름을 바꾸면 경로가 바뀌어 기록이 끊긴다 — 커밋되는 값이 여전히 키의 일부다

## Decision

우리는 기기 단위 상태를 **클론 키**로 나누기로 한다. 클론 키는 하네스 루트에서 실행할 때
`git rev-parse --git-common-dir` 의 실제 경로와 `git rev-parse --show-prefix` 를 해시한 불투명 값이고(git 밖이면 루트의
실제 경로), 계산은 대상 리포의 공용 모듈 하나(`script/_clone_key.py`)가 한다. 키는 생성 파일에 들어가지 않는다 —
설정 값의 자리표시 `{clone}` 을 지표 기록 · 사용 기록 · CLI 가 실행할 때 푼다.

등록부는 `~/.harness/<클론 키>/project.json` 에 `{path, name}` 을 둔다. 이름은 표시에만 쓰고 판정에 쓰지 않는다.
같은 이름의 다른 등록은 거부하지 않고 알리기만 한다. UI 는 등록부 디렉터리를 읽지 않고 CLI 의 목록 명령 출력으로
프로젝트를 전환하며, 라우트 인자는 클론 키다. 0009 가 적은 등록부 경로(`~/.harness/<이름>/project.json`)는 이 구조가
대신한다. UI 가 쓰기를 CLI 로만 한다는 0009 의 결정은 그대로다.

같은 클론의 worktree 가 공통 디렉터리를 공유하므로 되돌림 규칙 없이 같은 키가 되고, 복사로 복제될 상태를 두지
않으므로 이 입력을 고른다.

## Consequences

- 같은 리포를 한 기기에 여러 번 클론해 각각 설치할 수 있다. 등록과 기록은 클론마다 따로다
- 생성 파일은 설정 값의 자리표시를 그대로 담는다. 모든 클론에서 같고 `harness check` 가 통과한다
- 키는 사람이 읽을 수 없다. UI 와 CLI 출력은 이름과 경로를 함께 보여 같은 이름의 클론을 구별한다
- 클론을 다른 경로로 옮기거나 git 밖 루트에서 나중에 `git init` 하면 키가 바뀌고 기록이 이어지지 않는다 — 감수한다
- `project.name` 이 키 형식이면 거부한다. 등록부의 최상위에서 키 디렉터리와 옛 이름 디렉터리를 이름 형식으로 가른다
- 옛 자리표시 `{project}` 는 `{clone}` 과 같은 값으로 풀리는 옛 별칭으로 남고, render 와 doctor 가 바꾸라고 알린다
- 옛 이름 디렉터리의 기록은 install · render 가 등록부 잠금 안에서 키 아래로 옮긴다. 옛 경로를 대신 읽는 경로는 두지 않는다
- 0010 의 나머지 결정(홈 아래 JSONL 스팬 파일, 프롬프트 · 명령줄 · 본문을 남기지 않음, 기록은 부수 효과)은 위치만 바뀌어 그대로 이어진다
