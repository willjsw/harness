# 4. Review rounds are counted by one script

Date: 2026-09-23

## Status

Accepted

## Context

리뷰 루프는 끝나야 한다. 회차 상한과 "같은 파일에 같은 지적이 반복되면 코드가 아니라 명세가 틀린 것"
이라는 신호가 필요한데, 세는 주체가 여럿이면 세지 않은 회차가 상한 밖에 남는다. 오케스트레이터 세션이
서브에이전트로 리뷰를 돌리면 회차를 세는 경로를 건너뛴다.

검토한 대안.

- 세션이 회차를 센다. 세션은 재시작되고, 어느 기기에서 이어 돌리든 같은 수를 알 방법이 없다
- 리뷰어 계약이 자기 회차를 안다. 계약은 자기 러너도 다음 역할도 모르는 것이 원칙이다

## Decision

우리는 `script/review-mr.sh` 하나가 diff 조회·리뷰·등록·회차 라벨 갱신·상한 판정을 모두 맡게 하고,
절차는 그 종료 코드만 따르게 한다. 회차는 원격 리뷰 요청의 라벨(`<prefix>:<N>`)에 붙어 어느 기기에서
이어 돌리든 유지된다. 반복 지적은 `post-review.sh` 가 로컬에 누적한다 — 종료 보장이 아니라 신호다.

## Consequences

- 루프의 리뷰 수단은 이 스크립트 하나다. `code-reviewer` 서브에이전트는 사용자가 직접 부를 때만 쓴다
- 러너가 CLI 인 역할을 절차의 agent 단계로 부르면 render 가 거부한다 — 세는 경로를 건너뛰기 때문이다
- 판정은 등급 집계(blocker·major 건수)이고 리뷰 본문의 `REVIEW_VERDICT` 는 계약 준수 확인용이다.
  집계 절이 없거나 선언이 없으면 종료 코드 2 로 멈춘다
- 종료 코드 2 는 PASS 가 아니다. 절차는 출력의 인상이 아니라 종료 코드로만 분기한다
