# 22. Repeat findings history lives on the review request

Date: 2026-10-10

## Status

Proposed

## Context

리뷰 루프의 보조 상한은 "한 파일에 blocker·major 가 연속으로 나오는 회차" 다. 0004 Decision 은 그 이력을 이렇게 두었다 —
"반복 지적은 `post-review.sh` 가 로컬에 누적한다 — 종료 보장이 아니라 신호다". 이력 파일은
`<git 공통 디렉터리>/work-loop/review-findings-<번호>.tsv` 이고(`docs/spec/71-issue-worktree-run.md` 7절), 같은 클론의
worktree 끼리만 나눠 쓴다.

같은 리포를 여러 사람 · 여러 클론이 돌리게 된다. 조직 공용화 로드맵은 서버를 두지 않고 forge 를 공유 상태의 정본으로
쓴다. 클론 A 가 2회차까지 돌린 리뷰 요청을 클론 B 가 3회차부터 이어 돌리면 B 는 반복 회차를 0 부터 센다. 주 상한인 회차
라벨은 원격 리뷰 요청에 붙어 있어 이 문제가 없다.

제약과 사실.

- `post-review.sh` 머리글은 원격 복원을 기각해 두었다 — "댓글을 파싱해 이력을 되살리는 방식은 형식 변경에 취약하고, 틀린
  상한은 없는 것보다 나쁘다". 0014 이후 요약 댓글은 하네스가 렌더링하고, 만드는 코드와 읽는 코드가 한 모듈에 있다
  (0014 Consequences)
- 판정을 내는 등록 쪽은 지금 스레드를 읽지 않는다. 리뷰 입력은 회차 라벨을 올린 뒤 직전 요약 하나만 읽고, 읽지 못해도
  경고만 낸다. 반복 회차를 다시 세려면 `review.repeat_file_max - 1` 회차 이상의 요약이 필요하다
- 댓글은 사람이 지우거나 고칠 수 있다. forge 의 스레드 노트 정규화(0006 의 어댑터 계약)에는 작성자가 없다
- 여러 사람이 각자 계정으로 등록하므로, 요약을 쓴 계정 하나로 거르는 규칙은 성립하지 않는다

검토한 대안.

- 로컬 누적을 그대로 둔다. 클론이 바뀌면 0 부터 세는 증상이 남는다
- 원격으로 옮기고 반복 카운트를 종료 보장으로 올린다 — 이력을 조회 · 해석하지 못하면 리뷰 전에 종료 코드 2 로 멈춘다.
  댓글을 사람이 지우거나 고칠 수 있어 원격으로 옮겨도 보장이 성립하지 않는다. 지금의 "맥락 조회 실패는 리뷰를 막지
  않는다" 를 반복 판정 입력에 한해 뒤집어야 하고, 스레드 조회를 회차 라벨 갱신 앞으로 옮겨야 한다
- 결정 기록 없이 명세만 고친다. 0004 Decision 이 반대 방향을 말하는 채로 남아, 하위 근거가 상위 근거를 덮는다
- 요약 댓글에 판정 데이터 JSON 전체를 남긴다. 0014 스키마가 바뀔 때마다 옛 댓글을 읽는 호환을 지녀야 하고, 댓글 길이가
  대략 두 배가 되어 forge 의 본문 상한에 닿으면 등록이 실패한다
- 최소 기록에 작성자 필터를 더한다. 어댑터 계약의 노트 정규화에 작성자를 넣고 세 어댑터 · 페이크 · 자체 검사를 고쳐야
  한다. 등록하는 계정이 여럿이라 결국 쓰기 권한자 판정까지 어댑터가 해야 한다

## Decision

우리는 반복 지적 이력을 리뷰 요청의 요약 댓글 마지막 줄의 **요약 기록**(형식 판별자와 그 회차의 blocker·major 반복 키)으로
남기고, 리뷰 등록이 판정 전에 그 리뷰 요청의 스레드를 조회해 이전 요약들의 기록에서 연속 회차를 다시 세게 한다. 반복
카운트는 보조 신호로 남는다 — 스레드를 조회하지 못하거나 기록을 읽지 못한 회차는 연속을 끊고 경고만 내며, 루프의 종료는
회차 라벨이 보장한다. 기록은 판정 데이터 스키마와 따로 두고, 요약 노트는 작성자를 가리지 않는다.

종료 보장으로 올리지 않는 것은 댓글이 사람 손에 열려 있어 보장이 성립하지 않기 때문이고, 판정 데이터 전체를 남기지 않는
것은 이력이 판정 스키마 개정을 따라가지 않게 하려는 것이다.

## Consequences

- 0004 Decision 의 마지막 문장 "반복 지적은 `post-review.sh` 가 로컬에 누적한다 — 종료 보장이 아니라 신호다" 가운데 "로컬에
  누적한다" 를 이 결정이 대체한다. "종료 보장이 아니라 신호다" 와 0004 의 나머지(회차를 한 주체가 센다, 회차 라벨이 원격에
  붙는다, 절차는 종료 코드로만 분기한다)는 그대로다
- 어느 클론에서 이어 돌려도 같은 연속 회차를 센다. 클론 로컬 이력 파일은 만들지도 읽지도 쓰지도 않는다. 이미 있는 파일은
  하네스가 지우지 않는다
- 리뷰 등록이 forge 를 한 번 더 부른다(스레드 조회). 어댑터 계약은 늘지 않는다 — 리뷰 입력이 쓰는 스레드 조회를 함께 쓴다
- 등록된 댓글은 영구히 남는 데이터다. 기록의 형식을 바꾸면 판별자를 올리고, 다른 판별자의 기록은 읽지 못한 기록이 되어 그
  자리에서 연속이 끊긴다. 이 형식 전에 등록된 요약도 같다 — 진행 중인 리뷰 요청은 그 뒤부터 센다
- 위조된 기록 줄이 할 수 있는 일은 거짓 종료 코드 3(사람에게 넘김)과 반복 신호의 누락뿐이다. 감수한다
- 요약을 사람이 지우거나 고치면 연속 회차가 달라진다. 감수한다
- 재구성은 한 리뷰 요청에 등록자가 한 번에 하나라고 가정한다. `work` 경로에서는 착수 잠금(0023)이 그것을 지키고, 손으로 부른
  리뷰 명령끼리의 동시 실행은 지원하지 않는다
