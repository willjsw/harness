# 9. The UI writes only through the CLI

Date: 2026-09-24

## Status

Accepted

## Context

`.ai/project/` 를 채우지 않으면 하네스가 판단 근거를 잃는데, CLI 와 IDE 로 채우기는 어렵다. 웹 UI 가
필요했다. UI 가 설정을 고치는 로직을 갖기 시작하면 검증·되돌림·렌더가 두 곳에 생기고 한쪽이 낡는다.

검토한 대안.

- UI 가 TOML 을 직접 읽고 쓴다. 검증 규칙이 CLI 와 UI 에 이중으로 생긴다
- 서버를 외부에 노출. 로컬 파일을 쓰는 동작이라 위험하다

## Decision

우리는 UI 가 파일과 설정을 읽어 보이기만 하고, 쓰기는 전부 CLI 명령(`set`·`steps`·`checks`·`render`)을
서브프로세스로 부르게 한다. 검증·되돌림·렌더는 CLI 가 한다. 서버는 루프백에만 묶고, 등록된 프로젝트
목록(`~/.harness/<이름>/project.json`)으로 프로젝트를 전환한다. 역할·절차의 파일 경로는 UI 가 짓지
않고 `harness schema` 가 준다.

## Consequences

- UI 의 순수 함수만 단위 테스트한다. 화면과 서버 액션은 자동 테스트가 없다
- 프로젝트에 고정된 하네스가 옛 버전이면 UI 가 재설치를 안내한다 — 새 명령을 모르는 사본이다
- 문서 저장 전 검사(정적 + 저렴한 모델)는 결과를 보이기만 하고 저장할지는 사람이 정한다
- 기기 단위 기록(`tools.json`)은 등록부에 두되 프로젝트로 보이지 않는다
