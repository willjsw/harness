# 15. Detect changes to the pinned copy and managed files

Date: 2026-09-29

## Status

Proposed

## Context

대상 리포는 설치 시점의 하네스 사본(`.harness/bin` · `.harness/templates`)을 고정하고 그 사본이 그 리포의
정본이다(0005). 사본은 파이썬 소스와 텍스트 템플릿이라 리포에 쓰기 권한이 있는 누구나 고칠 수 있다.
관리 파일(`script/` · `.ai/templates/` 등)은 render 가 그대로 덮는다(0002) — 사람이 고친 내용은 다음
render 에서 알림 없이 사라진다.

검사를 도는 것도 그 사본 자신이다. pre-commit · `script/run-lint-test.sh` · CI 는 `.harness/bin/harness`
를 부르고, 전역 CLI 도 사본이 있으면 그쪽으로 넘긴다(`delegate()`). 사본을 고치면 모든 검사가 고친 기준으로
돈다. `.harness/managed` 는 경로 목록뿐이어서 `check` · `doctor` 는 관리 파일과 사본이 바뀌었는지 알 수 없다.

리포 밖에서 사본과 비교할 수 있는 기준은 이 기기에 설치된 전역 CLI 하나다. 그것도 고정 버전과 같은
버전일 때만 같은 파일을 갖는다. 명세는 `docs/spec/58-separate-managed-and-project-parts.md` 2절 · 4절 · 5절.

검토한 대안.

- 사본을 바이너리(zipapp 등)로 묶는다. 파이썬 아카이브는 풀어서 고칠 수 있어 막지 못하고, 빌드 단계와
  Homebrew 포뮬러 변경이 더해진다. 목표가 감지라면 얻는 것이 없다
- 전역 CLI 가 불일치를 보면 넘기기를 거부한다. 전역 CLI 가 같은 버전이면 파일 하나의 변경으로 넘겨받는
  명령 전부가 멈추고, 그 명령에 기대는 UI 홈(`harness status`)까지 멈춘다
- 관리 파일은 고정 사본의 `.harness/templates/managed/` 와 바로 비교하고, sha256 은 `.harness/bin` ·
  `.harness/templates` 에만 기록한다. 매니페스트 형식 변경이 사본 줄로 좁아진다. 대신 관리 파일 대조가
  고정 사본이 온전하다는 전제에 기대 — 사본의 템플릿과 관리 파일을 함께 고치면 대조가 통과한다 — 사본이
  없는 소스 리포에서는 다른 비교 규칙이 필요하다. 명세는 관리 파일과 사본을 같은 `<sha256>  <경로>` 줄로
  기록하고 같은 규칙으로 대조하는 쪽을 택했다

## Decision

우리는 고정 사본과 관리 파일의 변경을 막지 않고 감지한다.

- install 은 사본을 깐 직후 `.harness/bin` · `.harness/templates` · `.harness/VERSION` 의 sha256 을, render 는
  자기가 깐 관리 파일의 sha256 을 `.harness/managed` 에 `<sha256>  <경로>` 줄로 기록한다. render 는 사본의
  해시를 다시 계산하지 않는다 — 계산하면 고친 사본의 해시가 기록된다
- `check` · `doctor` 는 그 기록과 현재 파일을 대조해 `modified managed file` · `missing managed file` 을 보고한다.
  해시가 없는 옛 형식 줄은 비교하지 않는다
- 전역 CLI 는 고정 사본으로 넘기기 전에, 고정 버전이 자기 버전과 같을 때만 사본을 자기 파일과 바이트
  단위로 비교한다. 다르면 경고를 내고 그대로 넘긴다. 버전이 다르거나 읽히지 않으면 비교하지 않고
  `cannot verify` 한 줄을 낸다

바이너리로 묶지 않는 것은 막을 수 없기 때문이고, 넘기기를 거부하지 않는 것은 감지가 목표이고 파일 하나의
변경이 UI 까지 멈추게 하지 않기 위해서다.

## Consequences

- 0005 를 대체하지 않고 보완한다. 사본은 여전히 그 리포의 정본이고 전역 CLI 는 여전히 넘긴다 — 넘기기 전에
  대조 한 번이 더해질 뿐이다
- 0002 는 그대로다. 관리 파일은 여전히 render 가 덮는다. 달라지는 것은 덮기 전의 변경이 `check` · `doctor` 에
  보인다는 것이다
- `.harness/managed` 형식이 모든 설치본에서 바뀌고 리포에 커밋된다. `sha256sum` 과 같은 형식이라 하네스 없이
  `shasum -a 256 -c` 로도 확인된다. 옛 형식은 읽고 다음 render 가 새 형식으로 쓴다. 옛 하네스 사본이 새 형식을
  읽으면 해시 토큰을 경로로 보고 없는 파일로 건너뛴다
- pre-commit · `run-lint-test.sh` · CI 는 고친 사본으로 돈다. 사본과 매니페스트를 함께 고치면 그 검사들은
  알아채지 못한다. 사본 변조를 잡는 것은 같은 버전의 전역 CLI 가 있는 기기의 대조뿐이고, 그것도 경고만 한다
- 전역 CLI 와 고정 버전이 다른 기기에서는 사본을 대조하지 못한다. 전역 CLI 가 같은 버전 번호의 수정된 작업
  트리이면 그 차이도 다름으로 보고된다
- 줄바꿈을 바꾸는 git 설정(`core.autocrlf`)으로 체크아웃하면 바이트가 달라져 `modified managed file` 로 보고된다
- 소스 리포(0013)는 사본이 없으므로 관리 파일 줄만 기록하고 전역 CLI 대조를 하지 않는다
