# 14. Review verdicts are structured data

Date: 2026-09-27

## Status

Proposed

## Context

리뷰 루프의 판정은 `post-review.sh` 가 리뷰어 출력의 마크다운을 읽어 낸다. `## 발견 사항` 절을 제목으로
찾고, 그 안의 `- [<등급>] …` 행을 세고, `REVIEW_VERDICT` 선언을 확인한다
(0004 Consequences). 판정이 마크다운 제목 수준과 행 문법에 기대므로, 리뷰어가 제목 수준을 바꾸거나
절 밖에 발견을 적거나 행 형식을 조금 어기면 집계가 달라진다. 같은 리뷰어 출력이 요약 댓글로 그대로
등록되므로, 댓글의 모양도 리뷰어가 정한다.

리뷰 루프 스크립트(`review-mr.sh` · `post-review.sh`)에는 마크다운 절 추출이 두 곳에 있고 종료 규칙이
다르다. 리뷰 입력을 만들 때 사람이 쓴 리뷰 요청 본문에서 목적·리뷰 요청 포인트 절을 뽑는 쪽은 같은
수준 이상의 다음 제목에서 끝나고 두 절이 없으면 본문 전체로 대체한다. 판정 쪽은 발견 절을 다음 제목에서
끝낸다. 이 중복을 정리하는 과정에서 판정 입력의 형식 자체를 다시 정하게 되었다
(`docs/spec/64-modularize-cli-review-scripts.md` 2~5절).

검토한 대안.

- 두 종료 규칙을 한 모듈의 함수 둘로 유지. 동작은 보존하지만 판정이 제목 수준·행 문법에 기대는
  취약성이 그대로 남는다
- 수준 인식 규칙(같거나 높은 수준 제목에서 끝남)으로 통일. 리뷰 출력 집계가 바뀌고 리뷰어 계약과
  절차 문구를 고쳐야 하는데, 제목에 기대는 약점은 남는다
- 다음 제목 규칙으로 통일. 사람이 쓴 리뷰 요청 본문의 추출이 하위 제목에서 잘리고 본문 대체가 사라진다
- 내장 파이썬을 파일로 옮기기만. 중복 정리를 달성하지 못한다
- 구조화 판정을 별도 이슈로 분리. 리팩터링과 계약 변경이 한 리뷰 요청에 섞이지 않지만, 사용자는 이
  이슈에 포함하기로 결정했다
- 벤더 CLI 의 출력 스키마 강제 옵션 사용. 벤더마다 옵션 유무와 형태가 다르고, 리뷰어 러너는 벤더
  선언(0008)으로 바뀔 수 있다

## Decision

우리는 리뷰어가 판정을 JSON 블록 하나로 내고, `post-review.sh` 가 표준 라이브러리로 그 블록을 엄격히
검증해 데이터로 집계하게 한다. 등록하는 요약·인라인 댓글은 같은 데이터로 하네스가 렌더링한다. 판정은
마크다운 제목·행 문법에 기대지 않고, 벤더 CLI 의 출력 스키마 강제 옵션에도 기대지 않는다 — 계약은
역할 계약 문서의 지시와 이 검증으로 성립한다. 사람이 쓴 리뷰 요청 본문의 절 추출은 판정이 아니므로
제목 기반 추출과 본문 대체를 유지한다.

## Consequences

- 0004 Consequences 의 "리뷰 본문의 `REVIEW_VERDICT` 는 계약 준수 확인용이다" 부분을 이 결정이 대체한다.
  판정은 여전히 등급 집계(blocker·major 건수)이고, 계약 준수 확인은 판정 데이터의 `verdict` 필드와
  스키마 검증이 맡는다. 0004 의 나머지(회차를 한 스크립트가 센다, 종료 코드로만 분기한다)는 그대로다
- 블록이 없거나 둘 이상이거나 스키마를 하나라도 어기면 아무것도 등록하지 않고 종료 코드 2 로 멈춘다.
  리뷰어가 형식을 어긴 회차는 사람이 원문을 보고 판단한다
- 블록 밖의 텍스트는 판정에도 댓글에도 닿지 않는다. 리뷰어가 블록 밖에 적은 설명은 사라진다
- 모든 설치본의 리뷰 역할 계약(`code-reviewer` · `security-guard` · `developer`)·표지(`harness-format.sh`)·
  절차 문서가 함께 바뀐다. 하네스를 갱신한 설치본은 옛 형식의 리뷰어 출력을 받지 않는다
- 등록 댓글의 모양은 하네스가 정한다. 다음 회차가 직전 요약과 인라인 발견을 알아보는 표지는 만드는
  코드와 읽는 코드가 같은 모듈에 있다
- 스키마가 늘거나 바뀌면 검증·렌더링과 두 역할 계약을 함께 고쳐야 한다. 회귀 테스트가 모듈의 키·허용 값과
  계약 문서의 일치를 본다
