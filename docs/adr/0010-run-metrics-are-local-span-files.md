# 10. Run metrics are local span files

Date: 2026-09-25

## Status

Accepted

## Context

절차가 얼마나 걸리고 토큰을 얼마나 쓰며 어디서 실패하는지 알아야 상한과 절차를 조정할 수 있다.
기록이 리포에 남으면 커밋에 섞이고, 프롬프트와 본문이 남으면 민감 정보가 샌다. 기록 실패가 실행
결과를 바꾸면 안 된다.

검토한 대안.

- 리포 안에 기록. 커밋 대상이 되고 기기마다 다르다
- 외부 수집 서비스. 의존성과 네트워크가 생기고, 로컬 도구의 원칙과 맞지 않는다

## Decision

우리는 실행 지표를 홈 아래(`~/.harness/<프로젝트>/metrics`)의 JSONL 스팬 파일로 남기기로 한다.
명령·단계·에이전트·스크립트가 시작·끝 이벤트를 한 트레이스 아래에 남기고, 트레이스와 부모 스팬은
환경 변수로 자식에게 넘어간다. 프롬프트·명령줄·문서 본문은 남기지 않는다. 실패 로그는 끝부분만,
토큰·쿠키·이메일·홈 경로를 지운 뒤 남긴다. 기록은 부수 효과다 — 기록할 수 없어도 결과를 바꾸지 않는다.

## Consequences

- 오케스트레이터의 대화 기록에서 사용량만 가져와 실행·단계·역할에 붙인다. 본문은 저장하지 않는다
- 파일은 크기·보관 기간·전체 상한으로 로테이션한다. 디렉터리 0700, 파일 0600
- 점검(doctor)이 검증을 돌릴 때는 기록하지 않는다(`HARNESS_METRICS=off`) — 열 때마다 실행이 쌓였다
- 회귀 테스트는 바깥 실행의 트레이스를 물려받지 않아야 한다. 검증 스크립트 아래에서 돌 때 드러났다
