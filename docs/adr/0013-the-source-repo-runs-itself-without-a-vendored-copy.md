# 13. The source repo runs itself without a vendored copy

Date: 2026-09-26

## Status

Accepted

## Context

하네스 개발 리포 자신에게도 하네스가 필요하다. 그런데 리포 루트의 `harness.toml` 이 대상 리포로
복사되는 기본값이어서 이 리포 자신의 설정을 둘 자리가 없었고, CLI 는 자기 리포 실행을 명시적으로
거부했다. 일반 프로젝트처럼 `.harness/` 에 사본을 고정하면(0005) 자기 자신의 복제가 리포에 들어가고,
템플릿을 고칠 때마다 사본과 작업 트리가 어긋난다.

검토한 대안.

- 일반 프로젝트와 같이 사본을 고정. 템플릿 한 줄을 고칠 때마다 두 곳이 바뀌고, 생성물이 작업 트리가
  아니라 지난 사본을 따라간다
- 기본값을 루트에 두고 자기 설정을 다른 파일명으로. `load()` 와 UI·훅이 루트 `harness.toml` 을 전제한다

## Decision

우리는 기본 설정을 `src/templates/harness.toml` 로 옮기고, 리포 루트의 `harness.toml` 은 언제나 그 리포
자신의 설정이게 한다. 하네스 자체(CLI·템플릿·UI·테스트)는 `src/` 아래에 두고, 소스 리포는 사본을
고정하지 않고 자기 `src/bin/harness` 로 돈다. `install` 은 등록과 렌더만 하며, 어느 CLI 로 부르든 소스
리포의 것으로 넘어간다. 훅과 검증 일괄은 `.harness/bin/harness` 가 없으면 `src/bin/harness` 를 쓴다.

## Consequences

- 소유 문서 본문은 변수 치환 뒤에 넣는다 — 이 리포의 아키텍처 문서가 `{{VAR}}` 표기를 적자 render 가
  멈췄다. 템플릿 엔진을 쓰는 다른 프로젝트도 같은 결함을 만났을 것이다
- 회귀 테스트가 검증 스크립트 아래에서 돌게 되어 지표 문맥 격리가 필요해졌다(0010)
- Homebrew 포뮬러는 `src/` 아래를 `libexec` 에 넣는다. 전역 CLI 가 옛 버전이면 이 리포에서 `install`
  을 부르지 않는다 — 사본을 만들어 버린다
- 이 리포의 훅·가드는 자기 생성물로 돈다. 보호 문서를 고치려면 사람이 직접 한다
