# 사용 기록의 브랜치 유형 분류

사용 기록(`script/usage-log.sh`)이 한 줄마다 남기는 브랜치 유형(5번째 필드)을 어떻게 정하는지와,
설정을 읽지 못할 때 기록기가 어떻게 끝나는지를 정한다.

정본은 `src/templates/managed/script/usage-log.sh` 와 `src/templates/managed/script/test-usage-log.sh` 다.
이 리포의 `script/` 아래 같은 이름의 파일은 거기서 설치된 사본이다.

## 1. 값의 출처

브랜치 유형 판정에 쓰는 값은 전부 `script/harness.env` 에서 받는다. 기록기 본문에 브랜치 이름이나
태그 이름을 적지 않는다.

| 판정 | 설정 값 | 정본 설정 키 |
|---|---|---|
| 보호 브랜치 | `PROTECTED_BRANCHES` (공백 구분 목록) | `harness.toml` 의 `branches.protected` |
| 작업 브랜치 태그 | `COMMIT_TAGS` (`\|` 구분 목록) | `harness.toml` 의 `commit.tags` |

설정을 바꾸고 `harness render` 를 돌리면 기록기를 고치지 않아도 분류가 따라 바뀐다.

## 2. 분류 규칙

현재 브랜치 이름(`git branch --show-current`)을 아래 순서로 판정하고, 처음 맞는 것을 쓴다.

| 순서 | 조건 | 기록 값 |
|---|---|---|
| 1 | 브랜치 이름이 비었다 (분리된 HEAD, git 저장소가 아님) | `-` |
| 2 | 브랜치 이름이 `PROTECTED_BRANCHES` 의 항목 하나와 정확히 같다 | `protected` |
| 3 | 브랜치 이름이 `<태그>/` 로 시작하고, 그 `<태그>` 가 `COMMIT_TAGS` 의 항목 하나와 정확히 같다 | 그 `<태그>` |
| 4 | 그 밖 | `unknown` |

- **설정의 보호 브랜치 전부가 `protected` 로 분류된다.** 목록에 몇 개가 있든, 어떤 이름이든 같다
- 판정은 목록의 **항목 단위 일치**로 한다. `|` 를 담은 설정 값을 셸 `case` 패턴 자리에 변수로
  넣는 방식은 쓰지 않는다 — POSIX sh 는 변수 확장 결과의 `|` 를 대안으로 해석하지 않아 어떤
  브랜치도 맞지 않는다
- 설정 태그에 없는 접두사의 브랜치(`hotfix/x` 등), 슬래시 없이 태그 이름만인 브랜치(`feat`)는 `unknown` 이다
- 설정 값이 비어 있으면 그 판정은 아무 브랜치에도 맞지 않는다 — `PROTECTED_BRANCHES` 가 비면
  `protected` 가 없고, `COMMIT_TAGS` 가 비면 순서 3 이 없다

## 3. 설정을 읽지 못할 때

`script/harness.env` 가 없거나 읽을 수 없으면 **아무것도 기록하지 않고 종료 코드 0 으로 끝난다.**

- 기록기는 source 하기 전에 그 파일이 있고 읽을 수 있는지 확인한다. 확인 없이 source 해서 셸이
  비0 으로 끝나는 일이 없다
- 기록 파일을 만들거나 기존 기록에 줄을 더하지 않는다 — 설정 없이 판정한 분류를 남기지 않는다
- stdout·stderr 에 아무것도 내지 않는다
- 기록기의 "항상 0 으로 끝난다" 계약(스크립트 머리글, `script/README.md` 의 `usage-log.sh` 행)은 그대로다

## 4. 기록 형식과 집계

- 기록 한 줄의 형식(`<ISO시각>|<종류>|<출처>|<상세>|<브랜치유형>`, 필드 5개)은 바뀌지 않는다
- `script/usage-report.sh` 는 브랜치 유형 필드를 읽지 않는다. 집계 쪽 변경과 이미 남은 기록의
  이관은 없다

## 5. 회귀 테스트

`test-usage-log.sh` 에 아래 케이스를 둔다. 원격을 부르지 않고 임시 디렉터리에서 돈다.

| 케이스 | 확인하는 것 |
|---|---|
| 보호 브랜치 분류 | 설정 `PROTECTED_BRANCHES` 의 **모든 항목**에 대해, 그 이름의 브랜치에서 기록하면 브랜치 유형이 `protected` 다. 목록에 기본 통합 브랜치(`develop`)가 포함된 설정에서 그 브랜치도 `protected` 로 나온다 |
| 태그 브랜치 분류 | 설정 `COMMIT_TAGS` 의 항목으로 만든 `<태그>/<이름>` 브랜치의 브랜치 유형이 그 태그다 |
| 설정 밖 접두사 | 설정 태그에 없는 접두사의 브랜치는 `unknown` 이다 |
| 설정 누락 | `script/harness.env` 가 없는 배치에서 기록기를 부르면 종료 코드가 0 이고 기록 파일에 줄이 생기지 않는다 |

- 브랜치 이름과 태그 이름은 테스트 본문에 박지 않고 `script/harness.env` 의 값에서 가져온다 —
  이름을 박아 두면 설정을 바꿀 때 테스트가 조용히 다른 것을 본다
- 설정 누락 케이스는 이 리포의 `script/harness.env` 를 지우거나 옮기지 않는다. 기록기를 임시
  디렉터리에 배치해 설정이 없는 상태를 만든다
- 분류 케이스는 임시 git 저장소에서 브랜치를 만들어 돈다
