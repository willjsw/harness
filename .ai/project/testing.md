### 무엇을 어느 수준으로 검증하나

- 하네스가 약속하는 셋을 `src/test/render-test.sh` 가 본다 — 설정 하나를 고치면 그것을 쓰는 생성 파일이 **전부** 따라 바뀌는가, 생성 파일을 손대면 `check` 가 잡는가, 불변식 위반과 성립하지 않는 조합이 `render` 를 막는가. 케이스는 `UT-<번호>` 블록 하나가 한 약속이다
- 대상 리포에 깔리는 관리 스크립트는 각자 `script/test-<이름>.sh` 를 갖는다(리뷰 루프·이월 이슈·task 동기화·되감기·시크릿 스캔·가드·사용 기록). `render-test.sh` 가 임시 리포에 실제로 설치한 뒤 전부 돌린다 — 목록을 적지 않고 설치된 것을 세므로 새 테스트가 빠지지 않는다
- 자체 검사(`forge-selftest.sh`) 자신도 검사한다 — 계약을 지키는 페이크는 통과시키고, 위반을 주입한 페이크 6종은 전부 잡아야 한다
- UI 는 순수 함수(라벨·경로 검사·정적 문서 검사·차트 좌표·doctor 문구)만 `src/ui/lib/<모듈>.test.js` 로 본다(`node --test`). 화면·서버 액션은 자동 테스트가 없다
- 새 기능은 그 약속을 깨뜨리는 케이스를 먼저 추가한다. 되돌릴 수 없는 동작은 **닫는·지우는 동작보다 남기는 동작**을 더 많이 고정한다
- 케이스가 바꿔 보는 값은 `setup()` 이 알려진 상태로 고정한다 — 기본값과 같아지면 치환이 아무것도 바꾸지 않은 채 통과한다. 배포되는 기본값 자체는 UT-00 이 따로 본다
- 부정 검사("이 문자열이 없어야 한다")는 반대 조건에서 실제로 나타나는 문자열인지 확인하고 넣는다. 이미 바뀐 문자열을 찾는 검사는 아무것도 검사하지 않는다
- 터미널 출력에 한글이 섞이면 잡는다. BSD grep 에 `-P` 가 없어 python3 으로 찾는다 — 오류로 빠지면 검사가 통과해 버린다
- 시크릿 스캔은 잡는 쪽과 **지나가는 쪽**을 모두 고정한다. 오탐이 그 층을 죽인다

### 외부 의존을 어떻게 다루나

- 테스트는 원격도 대상 리포도 건드리지 않는다 — 임시 디렉터리에서만 돌고 끝나면 지운다. 설치 등록부는 `HARNESS_HOME` 으로 임시 위치에 두고, 바깥 실행의 지표 문맥(트레이스·부모 스팬)은 물려받지 않는다
- forge 는 `src/test/fake-forge.sh` 가 대신하고, 원격은 로컬 bare 리포다. 실제 forge 를 상대로 하는 어댑터 검증은 `script/forge-selftest.sh` 로 사람이 버려도 되는 리뷰 요청에만 돌린다
- 에이전트 CLI 는 부르지 않는다. 리뷰어·오케스트레이터는 스텁 실행 파일을 PATH 앞에 두어 두 벤더의 출력 형식만 흉내 낸다. `harness run` 은 `--dry-run` 으로 명령줄만 본다
- 이 리포 자신을 대상으로 도는 케이스는 소스 트리를 임시 디렉터리에 복제해서 본다
- 문서 저장 전 검사의 모델 판정은 테스트하지 않는다. 그 출력을 읽는 파서만 단위 테스트한다

### 하지 않는 것

- 실제 forge·에이전트 CLI·네트워크에 붙는 자동 테스트
- 이 리포의 작업 트리에 생성물을 쓰는 테스트
- 실제 시각·대기에 의존하는 테스트 — 지표의 시각은 고정값을 넣는다
